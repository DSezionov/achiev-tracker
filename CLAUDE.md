# Achievement Tracker — специфікація проєкту

Цей файл лежить у корені репозиторію. Його треба прочитати повністю перед тим, як змінювати код, і тримати актуальним, коли змінюються рішення.

## Що це

Особистий веб-застосунок для відстеження досягнень у відеоіграх. Власник сам знаходить гайд з досягненнями, вручну заносить гру, назви досягнень і умови їх отримання, а потім відмічає, які вже отримав. Progress bar показує прогрес.

- Хостинг: **GitHub Pages**, тобто тільки статичні файли, без сервера і без бази даних.
- Користувач один (власник). Реєстрації й акаунтів немає.
- Мова інтерфейсу: **українська**.

## Технічні рішення (не змінювати без погодження)

- **Vanilla HTML + CSS + JavaScript (ES modules).** Без фреймворків, без збирача (Vite/Webpack), без npm-залежностей у рантаймі. Сайт має працювати одразу після push у `main`.
- Маршрутизація через hash: `#/`, `#/game/<id>`, `#/game/<id>/edit`, `#/settings`. History API не використовувати, бо GitHub Pages не вміє робити fallback на index.html.
- Усі шляхи до файлів **відносні** (`./js/app.js`, а не `/js/app.js`), бо сайт живе за адресою `https://<user>.github.io/<repo>/`.
- У корені має бути порожній файл `.nojekyll`.
- Шрифти: системний стек (обрано його — без зовнішніх запитів, добре для офлайну).
- Жодних зовнішніх трекерів чи аналітики.

## Модель даних

Увесь стан зберігається як один JSON-об'єкт:

```json
{
  "schemaVersion": 1,
  "updatedAt": "2026-11-07T20:00:00.000Z",
  "games": [
    {
      "id": "g_k3j9x2",
      "title": "S.T.A.L.K.E.R. 2: Heart of Chornobyl",
      "platform": "Steam",
      "accent": "#c8a24a",
      "coverUrl": "",
      "guideUrl": "https://steamcommunity.com/sharedfiles/filedetails/?id=...",
      "notes": "",
      "createdAt": "2026-11-07T20:00:00.000Z",
      "sections": [
        {
          "id": "s_a1b2c3",
          "title": "Сюжет",
          "achievements": [
            {
              "id": "a_x7y8z9",
              "name": "Назва досягнення",
              "condition": "Умова отримання",
              "tip": "Необов'язкова порада з гайду",
              "missable": false,
              "done": false,
              "doneAt": null
            }
          ]
        }
      ]
    }
  ]
}
```

Правила:
- Порядок ігор, розділів і досягнень визначається порядком у масивах.
- У кожної гри є хоча б один розділ. Нова гра отримує розділ «Загальне». Якщо розділ у гри один, його заголовок не показується.
- `id` генерується через `uid(prefix)` (короткий випадковий рядок) і ніколи не змінюється.
- `updatedAt` оновлюється при кожній зміні стану.
- Прогрес (кількість і відсоток) рахується з `done` і **ніколи не зберігається** окремо.
- `store.js` містить функцію `migrate(state)`. При зміні схеми збільшувати `schemaVersion` і дописувати крок міграції.

## Прийняті рішення щодо реалізації

- Нова гра створюється за маршрутом `#/game/new/edit`: форма з полями гри, після «Створити гру» — перехід у редактор цієї гри.
- Редактор зберігає зміни одразу: текстові поля — на подію `change` (втрата фокусу / Enter), структурні дії — по кліку. Кнопки «Зберегти» немає.
- Ручний порядок ігор змінюється кнопками ↑↓ на картках, коли на головній обрано «Ручний порядок».
- DOM будується через `el()` з `utils.js`; текст користувача потрапляє лише в `textContent`. URL з даних проходять `safeUrl()` (тільки http/https), колір — `safeColor()`.
- Підрахунок прогресу: одна функція `progress(achievements)` у `store.js`; `gameProgress`, `sectionProgress`, `totalProgress` — обгортки над нею.
- Усі зміни даних — через `update()` у `store.js` (оновлює `updatedAt`, пише в localStorage, сповіщає підписників з `source`: `local` / `import` / `remote`).
- Порожній стан має `updatedAt: null`, щоб новий пристрій ніколи не перезаписав Gist порожніми даними.
- Налаштування інтерфейсу (тема, сортування, згорнуті розділи) — окремий ключ `achievement-tracker:prefs`, не синхронізуються.
- Перед «Замінити все», «Видалити всі дані» і перезаписом з Gist поточні дані зберігаються в `achievement-tracker:backup`; у «Налаштуваннях» є «Відновити».
- Сторінка гри при відмітці не перебудовується: оновлюються рядок і прогрес (без стрибків прокрутки).

## Збереження

1. **localStorage** (ключ `achievement-tracker:v1`) — основне сховище. Записувати після кожної зміни.
2. **Експорт / імпорт JSON** у «Налаштуваннях»: завантажити файл `achievements-YYYY-MM-DD.json` і відновити з файлу (з підтвердженням: «Замінити все» або «Додати ігри»).
3. **Синхронізація через GitHub Gist** (етап 3, див. нижче), щоб прогрес був однаковий на ПК і телефоні.

## Екрани та функції

### Головна (`#/`)
- Загальний прогрес по всіх іграх: великий progress bar, «N з M (X%)».
- Сітка карток ігор. На картці: обкладинка або кольорова плашка з `accent`, назва, платформа, progress bar, «N / M», бейдж «100%», коли гру закрито.
- Кнопка «+ Додати гру».
- Сортування: за ручним порядком, за назвою, за прогресом.

### Сторінка гри (`#/game/<id>`)
- Шапка: назва, посилання на гайд, sticky progress bar гри (лишається видимим під час прокрутки).
- Розділи можна згортати. Біля заголовка розділу — його власний прогрес «N / M».
- Рядок досягнення: великий чекбокс, назва, умова, бейдж «Можна пропустити» (якщо `missable`), розгортна «Порада» (якщо є `tip`), дата отримання (якщо `done`).
- Клік по рядку або чекбоксу перемикає `done`. Progress bar анімовано оновлюється.
- Фільтри: «Усі / Залишилось / Отримані / Можна пропустити».
- Пошук за назвою, умовою й порадою, без урахування регістру.
- Кнопка «Редагувати».

### Редактор (`#/game/<id>/edit` і створення нової гри)
- Поля гри: назва (обов'язкова), платформа, колір акценту (color picker), URL обкладинки, URL гайду, нотатки.
- Розділи: додати, перейменувати, видалити (з підтвердженням, якщо в розділі є досягнення), змінити порядок кнопками ↑↓.
- Досягнення: додати, редагувати inline, видалити, перемістити ↑↓ або в інший розділ.
- Форма швидкого додавання одного досягнення: назва + умова + порада + чекбокс «можна пропустити», Enter зберігає й очищає форму для наступного.
- **Масовий текстовий імпорт** (див. нижче).
- Видалення гри — лише з підтвердженням (потрібно ввести назву гри).

### Масовий текстовий імпорт
Текстове поле, куди вставляється список. Формат:

```
## Сюжет
Новий старий друг | Пройти Кордон і поговорити з Сидоровичем.
! Посмішка Марти | Врятувати напарника-долгівця | Петра вбивай лише після нагороди.
## Колекціонування
Сталкерстрайк | Убити 50 сталкерів хедшотами.
```

- `## Назва` створює новий розділ (або дописує в наявний з такою самою назвою).
- Рядок досягнення: `Назва | Умова | Порада`. Порада необов'язкова.
- `!` на початку рядка означає `missable: true`.
- Порожні рядки ігноруються.
- Перед збереженням показується попередній перегляд: «Буде додано: N розділів, M досягнень».

Також приймається JSON однієї гри (у форматі об'єкта гри без `id`, `done` і `doneAt`; їх згенерує застосунок).

### Налаштування (`#/settings`)
- Експорт/імпорт JSON.
- Синхронізація з Gist (етап 3).
- «Скинути прогрес гри» (усі `done = false`) і «Видалити всі дані», обидва з підтвердженням.

## Синхронізація через GitHub Gist (етап 3)

- Користувач вставляє в налаштуваннях Personal Access Token з одним правом `gist`. Токен зберігається **лише в localStorage цього браузера** і ніколи не потрапляє в код чи репозиторій.
- При першому підключенні застосунок створює **секретний** Gist з файлом `achievements.json` і запам'ятовує його `gistId`. На другому пристрої можна вставити той самий токен і `gistId` (або знайти Gist автоматично за описом `achievement-tracker-data`).
- Під час відкриття: завантажити Gist. Якщо там `updatedAt` новіший за локальний, підтягнути дані з Gist; якщо старіший, відправити туди локальні.
- Після змін: відправка з debounce 2 секунди.
- Індикатор стану в шапці: «Синхронізовано / Синхронізація… / Офлайн / Помилка». Помилки мережі не повинні ламати роботу: localStorage лишається джерелом правди.
- Перед кожним перезаписом даних з Gist автоматично зберігати резервну копію в localStorage (`achievement-tracker:backup`).
- Конфіг (токен, `gistId`, `lastSynced`) — у `achievement-tracker:gist`. Перевірка на свіжість також при поверненні у вкладку і раз на 2 хв.
- Конфлікт (дані змінились і локально, і в Gist після останньої синхронізації): перемагає новіший `updatedAt`, версія, що програла, — у резервну копію, користувач бачить сповіщення.
- Під час підключення до наявного Gist, якщо дані є з обох боків, користувач обирає: «Взяти з Gist» або «Відправити локальні».
- API: `GET/PATCH https://api.github.com/gists/<id>`, `POST https://api.github.com/gists`, заголовок `Authorization: Bearer <token>`.

## Дизайн

- Темна тема за замовчуванням, світла як опція (перемикач, вибір зберігається).
- Усі кольори, відступи, радіуси й шрифти задані змінними в `css/tokens.css`, щоб легко перефарбувати.
- Колір `accent` гри застосовується на її сторінці (progress bar, чекбокси, акценти) через CSS-змінну `--game-accent`.
- Mobile-first: зручно відмічати з телефона під час гри. Мінімальна зона дотику 44px.
- Доступність: справжні `<input type="checkbox">` з `<label>`, видимий фокус, контраст WCAG AA, `prefers-reduced-motion` вимикає анімації.
- Мікроанімація при отриманні досягнення (коротке підсвічування рядка). При 100% у гри показується повідомлення про завершення.

## Етапи реалізації

Статус: етапи 1–4 реалізовано (2026-11-07).

Кожен етап завершується робочим станом, який можна запушити.

**Етап 1 — MVP**
- Структура файлів, `.nojekyll`, роутер, `store.js` з localStorage.
- Головна з картками і загальним прогресом.
- Сторінка гри: розділи, перемикання `done`, progress bar.
- Редактор: створення й редагування гри, розділів, досягнень (по одному).
- Експорт/імпорт JSON.
- `data/example.json` з 1–2 тестовими іграми.

**Етап 2 — Зручність**
- Масовий текстовий імпорт з попереднім переглядом.
- Фільтри, пошук, згортання розділів, сортування на головній.
- Зміна порядку ↑↓, переміщення між розділами.
- Світла/темна тема.

**Етап 3 — Синхронізація**
- `sync-gist.js` і UI в налаштуваннях, індикатор стану.

**Етап 4 — Опційно**
- PWA (manifest + service worker) для встановлення на телефон і роботи офлайн.
- Статистика: дата останнього отриманого досягнення, кількість за тиждень/місяць.

## Критерії готовності (перевіряти після кожного етапу)

- Сайт відкривається через локальний сервер (`python3 -m http.server 8000`) без помилок у консолі.
- Після перезавантаження сторінки всі дані на місці.
- Progress bar гри, розділу і загальний збігаються з реальною кількістю відмічених.
- Експорт → «Видалити всі дані» → імпорт повністю відновлює стан.
- Інтерфейс нормально виглядає на ширині 360px і 1440px.
- Немає абсолютних шляхів, які зламаються на `/<repo>/`.
- Будь-який текст від користувача виводиться через `textContent` або `escapeHtml()`, без сирого `innerHTML`.
